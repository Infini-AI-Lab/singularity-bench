# Fix the GPU batching service

`service.py` exposes a local HTTP API for `relu(x @ W + b)` on CUDA. The fixed
weights and bias are generated by `weights()`. POST `/infer` accepts JSON
`{"id": "request-id", "x": [[... eight floats ...], ...]}` and must return
`{"id": "request-id", "y": [[... four floats ...], ...]}` for that same input.
GET `/health` reports readiness. The service is deliberately small: no language
model, model downloads, or external services are involved.

Concurrent requests with different numbers of rows sometimes receive the wrong
outputs. Reproduce the bug, fix it while retaining GPU batching, and add
`test_regression.py`. That test must use the server URL from `SERVICE_URL`, send
concurrent requests with different row counts, and exit nonzero on a mismatch.
Preserve `weights()`, `compute_batch(items)`, and `serve(port, ready_path)` so
the public checker can exercise the service and observe GPU execution.

```sh
python3 service.py --port 8080
# In another command, or with the server in the background:
SERVICE_URL=http://127.0.0.1:8080 python3 test_regression.py
```

Start, inspect, and stop your own server as needed. The public checker also starts
a fresh server on a free port, tests concurrent requests against its own reference,
runs your regression test, checks GPU activity, and cleans up its server:

```sh
python3 /app/examples/run.py check gpu-batch-service --workspace "$PWD"
```
